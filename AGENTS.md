# SaikoUniversity — DOX Rail

## Purpose

University enrollment and tracking platform, fictionalized as Saiko University. Monorepo holding a
.NET 10 API and a React SPA that share a SQL Server database.

DOX is a binding work contract hierarchy. Read this file, then every `AGENTS.md` between the repo
root and the file you are about to edit. The nearest doc controls local details; no child doc may
weaken a parent rule.

## Ownership

This file owns:

- Solution file, shared build props, package version management
- Docker Compose local database
- Repository-wide naming conventions
- The DOX hierarchy itself and its Child DOX Index
- Secrets policy (`.env` local, `.env.example` committed)

Direct children own their own code, configuration, and verification.

## Local Contracts

### Naming

| Surface | Convention | Example |
|---|---|---|
| Display name | Saiko University | Login page, page titles, README |
| GitHub repo | `saiko-university` | Monorepo root |
| Solution | `SaikoUniversity.slnx` | .NET 10 XML solution format |
| Assemblies / root namespaces | Bare layer names | `Domain`, `Application`, `Infrastructure`, `Api` |
| Type names | Role-based only | `AppDbContext`, `AddInfrastructure()` |
| Test assemblies | `<Layer>.Tests` | `Api.Tests` |
| Frontend package | `saiko-university-web` | npm package name |
| Docker image | `saiko-university-api` | lowercase, hyphenated |
| Database | `SaikoUniversity` | Environment lives on the server |
| Kebab-case | DNS, URL, container names | `docker-compose.yml`, `saiko-uni-sql` |

Rules:

- Project folder, `.csproj` filename, assembly name, and root namespace always match.
  `src/Domain/` holds `Domain.csproj`, which builds `Domain.dll` with namespace `Domain.*`.
- Never name a type `Domain`, `Application`, `Infrastructure`, or `Api`. It clashes with the
  namespace of the same name. Type names stay role-based.
- Never embed the product name in type or method names.

Why bare layer names: this is a single-product, single-domain-model solution, so a product
prefix disambiguates nothing, and the bare name puts the architectural layer first.

The tradeoff, stated so nobody rediscovers it: two projects sharing a bare name cannot coexist
in one solution. Their assemblies overwrite each other in the output folder and the build fails
with a misleading `CS0234`, because only one of the two assemblies survives the copy. If a second
product or a second bounded context with its own `Domain` project enters this solution, prefix
every layer in that same change. Do not mix styles.

This is a deliberate convention for this repo, not a universal rule. Product-prefixed layers are
the safer default for multi-product repositories.

### Secrets

- `.env` is gitignored and holds local container secrets.
- `.env.example` is committed and documents every variable with no value.
- **The Development connection string is committed on purpose.**
  `appsettings.Development.json` holds the localhost Compose credentials (`sa` / `Dev!Pass123`)
  so a fresh clone runs with one command. It is a throwaway password for a local container that
  exists to be disposable, not a secret.
- Production credentials come from Azure Key Vault. Never commit a non-local connection string,
  an API key, or a token, regardless of environment.
- A credential that would still be sensitive if the container were destroyed belongs in `.env` or
  user secrets, not in a tracked JSON file.

### Build

- `net10.0`, nullable enabled, implicit usings, warnings as errors, enforced code style.
- Central Package Management is on. Declare `PackageVersion` in `Directory.Packages.props`; never
  put a `Version` attribute on a `PackageReference`.
- Project references flow inward only: Api -> Infrastructure -> Application -> Domain. Domain has
  zero project references.

### DOX workflow

1. Read this file, then each `AGENTS.md` on the path to the target file.
2. Do the work.
3. Re-walk the path and update every doc whose scope, contracts, structure, or index changed.
4. Report any docs intentionally left unchanged.

## Work Guidance

- Commit messages are generated by the `commit-message` skill (`.agents/skills/commit-message`).
  It never stages and never commits.
- Prefer role-based type names: `AppDbContext`, not `SaikoUniversityDbContext`.
- Keep `bin/` and `obj/` out of every doc's scope.
- Repository scripts live in `scripts/tools/`, use lowercase kebab-case `.ps1` filenames, resolve the
  repo root from `$PSScriptRoot`, set `$ErrorActionPreference = 'Stop'`, and are safe to re-run.
  They invoke tools with the command name that exists on a plain Windows install, not a pwsh-only
  one. Verb-Noun naming applies to functions inside a script, never to a filename.

## Verification

- Build: `dotnet build SaikoUniversity.slnx`
- Tests: `dotnet test SaikoUniversity.slnx`
- Database health: `docker compose ps` reports `healthy` for `saiko-uni-sql`
- Whitespace: `powershell -ExecutionPolicy Bypass -File scripts/tools/clean-whitespace.ps1`
- OpenAPI snapshot: `powershell -ExecutionPolicy Bypass -File scripts/tools/update-openapi.ps1`

## Child DOX Index

- `.agents/` — agent skills and agent-instruction assets checked into the repo
- `src/` — all production .NET projects and the layering contract between them
- `tests/` — one test project per src layer, plus shared test infrastructure
- `scripts/` — repository tooling, with its own naming and authoring rules
