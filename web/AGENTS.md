# web — Frontend

## Purpose

The Saiko University SPA. Owns the browser surface: routing, data fetching, and presentation. It
consumes the API through a generated client and never hand-writes a request.

## Ownership

- The Vite, TypeScript, Tailwind, and TanStack configuration
- The generated API client under `src/api/`
- The file-based route tree under `src/routes/`
- Feature folders under `src/features/`
- shadcn/ui components under `src/components/ui/`

## Local Contracts

### The API client is generated

- `src/api/` is generated by Orval from `artifacts/openapi/saiko-university.json`. **Never hand-edit
  anything in that folder.** Regenerate instead:

  ```powershell
  powershell -ExecutionPolicy Bypass -File scripts/tools/update-openapi.ps1
  npm --prefix web run api:generate
  ```

- `src/api/client.ts` is the one exception. It is the mutator Orval is pointed at, so it is
  maintained by hand. It is also the only file in `web/` that constructs an HTTP client. Feature code
  never imports `axios`; it calls a feature hook, which calls the generated client.

### One axios instance

- `apiClient` in `src/api/client.ts` is the only `axios.create` call in the project. Every generated
  request goes through it.
- It sets a **30 second timeout**. `fetch` has no timeout, and neither does axios unless one is
  configured, so an unreachable API would otherwise hang the UI indefinitely.
- Its response interceptor turns every failure into an `Error` whose `message` is readable by a user.
  That is why the interceptor exists: without it, a component needs to know axios response shapes
  just to display a failure.
- When authentication lands, the request interceptor in the same file is where the bearer token goes.
  One place, not per feature.
- `src/routeTree.gen.ts` is generated by `@tanstack/router-plugin`. Never edit it. It regenerates on
  every dev-server start and every build.

### Same-origin only

- The generated URLs already contain their full path, such as `/api/v1/programs`. The mutator must
  not prepend a base path. `VITE_API_BASE_URL` is an **origin**, not a path prefix. Setting it to
  `/api` produces `/api/api/v1/programs`.
- It is empty by default, which keeps every call same-origin. That is what Vite's dev proxy provides
  locally and what the API provides once it serves the built SPA. No CORS is configured, and none is
  needed under that shape.
- Setting an absolute origin is only correct for split hosting, which is not supported today.

### Feature folder shape

One folder per vertical slice, under `src/features/<slice>/`. The slice name matches the API tag,
which is what Orval splits on.

| File | Owns | Must not contain |
|---|---|---|
| `<Slice>Page.tsx` | Route component: loading, error, empty states | Query calls |
| `use<Slice>.ts` | Every query and mutation hook for the slice | JSX |
| `<Slice>Table.tsx` | Presentation. Receives rows as props | Hooks, queries, `fetch` |

- A component never calls `useQuery` directly. It calls the feature hook. That keeps query keys and
  mutation invalidations in one file.
- A presentational component never fetches. If a table needs data, the page passes it in.

### Stable references for TanStack Table

`columns` and `data` must be referentially stable across renders. Memoize both. This is the
documented cause of a tab-killing infinite loop.

- Never spread the rows array into `data`. Rows from the query cache are already stable; spreading
  them destroys that identity.
- Memoize any transformation. `data?.filter(...) ?? []` inline is the same bug wearing a disguise.
- Symptom: page loads fine, then locks the tab on an unrelated interaction such as opening a form
  or toggling a filter. F5 does not recover it. Look at reference stability in the table, not the
  interaction.
- Source: https://tanstack.com/table/v8/docs/faq

### Modals and table re-renders

A dialog opens on top of the same tree as the table. If that parent re-render makes `columns` or
`data` change identity, TanStack re-enters its row model and can loop until the renderer dies.
Keep `columns` and `data` memoized with stable deps, even while a modal is open over the table.

### URL search params and routing

- Route search parameter validation uses TanStack Router's native `validateSearch` function with
  plain TypeScript validation (no runtime schema library dependencies like Zod).
- Query keys and multi-word enum values in URLs use kebab-case (e.g. `not-accepting`).
- Clean URLs: default parameter values (`page=1`, default page size, empty filters) are omitted
  from the URL query string.

### Conventions

- `cn()` from `@/lib/utils` in every `className`. Never concatenate class strings.
- Design tokens only. A hex value or a raw color never appears in a component. Change the token in
  `src/index.css` and every component follows.
- `shadcn/ui` components live in `src/components/ui/`. Adding one is a copy, not an import from a
  package.
- Import through the `@/` alias. Never a relative path that climbs out of `src/`.

## Work Guidance

- Add a feature as a new folder under `src/features/`. Add a route file under `src/routes/` only
  when it needs its own URL.
- When the API contract changes, regenerate rather than adjusting types by hand. A type that does not
  match the API is worse than a build error.
- Run `npm run build` before committing. It type-checks the whole project, including generated code.

## Verification

- `npm --prefix web run build` — must succeed with no TypeScript errors
- `npm --prefix web run lint` — type-check only, no emit
- `npm --prefix web run dev` — must serve on port 5173 with no console errors
- With the API running: `http://localhost:5173/` renders the programs table with live data
- `npm --prefix web run api:generate` — must produce no diff when the API contract has not changed
